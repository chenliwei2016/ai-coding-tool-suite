# Tech Writing

产出清晰、结构化、可执行的技术文档，让人读得懂、照着做、能回溯。

## 适用场景（when）

- 写技术方案、设计文档、评审记录、复盘
- 写教程 / 操作指南 / 新人上手文档
- 需要把一段复杂思路讲清楚给团队看

## 输入（要拿什么进来）

- 要表达的内容 / 背景 / 目标读者
- 相关的决策理由、步骤、结果

## 核心步骤（流程）

1. **先定读者与目的**：给谁看、看完要能做什么——决定详略
2. **"为什么→是什么→怎么做"**：先给背景与决策理由，再结构呈现，最后落地步骤
3. **结构化组织**：分节、列表、表格、代码块，降低阅读负担
4. **抓住精华而非罗列**：提炼关键论断与决策理由，删冗余
5. **可执行可回溯**：给出可操作的步骤与验收，记录关键决策"为什么这么选"

## 评审/自检 checklist

- [ ] 读者读完知道"为什么 + 怎么做"了吗？
- [ ] 结构与层级清晰，重点突出？（不是流水账）
- [ ] 步骤是否可执行、有验收？
- [ ] 是否记录了关键决策背后的理由（而非只有结论）？

## 常见坑

- ❌ 只写"是什么"，漏了"为什么"——读者照着做但不懂取舍
- ❌ 平铺罗列、没有重点与层级，读起来像流水账
- ❌ 堆积术语，没考虑读者视角
- ❌ 只给结论不给理由，后人无法回溯当初决策

## 产出物

- 结构清晰、重点突出、可执行、可回溯的技术文档
